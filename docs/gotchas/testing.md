# Gotchas — Testing (pest, vitest, Playwright)

Moved verbatim from `CLAUDE.md` (the rule headlines stay there). Read this file before changing writing or debugging any test. Bullets that say «above» may now point into another file in `docs/gotchas/`.

- **A `->delay()` runs immediately on the `sync` queue connection.** A delay is a queue-driver feature and `sync` has no queue, so any test that exercises a session timeline must fake the timeline jobs — otherwise `CloseClassSessionJob` fires inside `OpenBroadcastRoom` and closes the session before the teacher joins, collapsing the timeline into a green test that proves the opposite of what it claims. ⚠️ **But a BARE `Queue::fake()` swallows the queued LISTENERS**, and that is now two modules' worth of vacuous assertions: `ChargeSeatsOnDelivery` and `AccrueUnitsOnDelivery` both hang off `SessionDelivered`, so "ten frozen seats ⇒ ten teaching units" becomes a confident claim about an empty table. `fakeSessionTimeline()` in `tests/Pest.php` is the one spelling — the five jobs a delay would misfire, and nothing else. Never add a class to that list to make an assertion pass.
- **Component logic is tested with `npm test` (vitest + jsdom); Playwright answers a different question.** The frontend had ONE test surface until the day three interface defects shipped together — a second tap that silently turned a right answer into a zero on a graded paper, a screen that offered to upload a video for an article, and a player that told every non-Safari student «صيغة غير مدعومة». None is reachable from the backend suite, and none was worth a Playwright run: that config builds for production and needs two servers, so nobody runs it inside a development loop. `npm test` needs neither and finishes in about two seconds. **The dividing line is the question, not the layer**: "does this component do what it says" is vitest; "does the product work end to end, and is it accessible" stays Playwright. Two configuration details are load-bearing — `include` is scoped to `src/**/*.test.{ts,tsx}` (the default would swallow `e2e/*.spec.ts` and die inside Playwright's runner), and globals are OFF so every test imports `describe`/`it`/`expect` by name and `npx tsc --noEmit` needs no test-only `types` entry. SC-012 (a player surviving a rejected segment) is measured here by mocking `hls.js` and calling the ERROR handler it registers; reproducing it for real would mean rotating a signing key against a live CDN mid-playback.
- **`npx playwright test` needs an API that can answer concurrently, or the *build* fails before a single test runs.** The committed config builds for production, and Next prerenders `signup/teacher` and `signup/parent/children` by fetching the API — in parallel workers. `php artisan serve` is PHP's built-in server with **one thread**, so it answers the first and refuses the rest: `TypeError: fetch failed … ECONNREFUSED`, then `Export encountered an error`. Start the API as `PHP_CLI_SERVER_WORKERS=8 php artisan serve --no-reload`. ⚠️ **Without `--no-reload` the variable is IGNORED** — measured 2026-09-02, and Laravel says so in a warning that scrolls past: «Unable to respect the `PHP_CLI_SERVER_WORKERS` environment variable without the `--no-reload` flag. Only creating a single server.» So the form this file carried until now produced a silently single-threaded server, which is the exact thing it was written to avoid. Measured on Windows the full matrix is **28 minutes**, not the four this file claimed — six projects, and CI's ubuntu runner is not this machine. Worth the trouble: the production run is 4 minutes and green, the same suite against `next dev` takes 31 and fails on `page.goto` timeouts that mean nothing.
- **`Queue::fake()` with no arguments makes half the billing suite assert zero rows.** The charge listener is queued, so a bare fake swallows it and "four attendance states ⇒ four consumption entries" becomes a confident assertion about an empty table. Fake the timeline jobs only — `Queue::fake([CloseClassSessionJob::class, SendSessionReportsJob::class])` — and let the charge run on `sync`. Calling the Action directly instead tests the arithmetic and proves nothing about the wiring.
- Playwright projects carry an authenticated `storageState` produced by `e2e/auth.setup.ts` so the panel can be audited. A spec that tests an anonymous visitor must opt out with `test.use({ storageState: { cookies: [], origins: [] } })`, or it silently tests a signed-in one.
- **`getContent()` escapes non-ASCII, so a leak assertion with an Arabic needle is vacuously true.** `expect($response->getContent())->not->toContain('حلُّ زميلي.')` never matches, whatever the payload holds — the body carries `حل...`. Every exposure test in this product asserts on Arabic text, so the whole file would pass against a response that leaked everything. `AssessmentExposureTest::bodyText()` re-encodes with `JSON_UNESCAPED_UNICODE`; the ASCII sentinels the Courses and Marketplace exposure tests use (`DRAFT_SENTINEL`, a distinctive English name) are the other way of being safe.
- **`Http::fake()` APPENDS stub sets and the first matching pattern wins.** So a test that fakes an empty answer and later re-fakes a populated one still gets the empty one — the earlier stub is still registered. It reads as a missing feature and invites "fixing" the assertion. Use ONE closure fake driven by state the test mutates (`BunnyIngestTest`, `BunnyDeleteTest`), and `Http::preventStrayRequests()` where the requirement is that no call happens at all (`manifest()` must not touch the network — it runs on every playback request, and a call there turns a provider slowdown into zero viewing instead of degraded viewing).
- **A test can be green because of the WRONG condition, and `US6` shipped nine of them that way.** Completing a teacher's exit has TWO bars — the books balanced (`FR-032`) and the announced notice run out (`FR-033`) — so every fixture with a live notice is refused whatever the ledger says. Deleting the settlement check **entirely** left all nine cases passing: the file that exists to prove `SC-013` proved the date. ⚠️ **The only thing that found it was removing the guard and re-running**; reading the assertions could not, because each one is individually true. The rule that falls out: when a check has more than one condition, a test of ONE of them has to neutralise the others in its fixture, or it is measuring whichever fires first. A second guard nothing measures was found in the same pass — the student exclusion below survived its own deletion, because the 403 it was written for came from somewhere else entirely.
- **A query-budget test does not catch a dropped eager load when the Resource uses `whenLoaded`.** Removing `->with('subject')` from the officer's queue produces no N+1 at all: the key is simply ABSENT, the page is one query cheaper, and a test measuring queries alone reports the regression as an improvement. The queue then lists requests with nobody's name against them. So the budget test asserts the field is PRESENT as well as that the cost is flat — the two assertions guard the two opposite mistakes, dropping the eager load and dropping the `whenLoaded` that makes it safe to have.
- **A test that joins a room must `Queue::fake([CloseClassSessionJob::class])`, or every later door answers 403 for the wrong reason.** `OpenBroadcastRoom` dispatches the close job with a `->delay()` for the end of the join window, and **a delay runs immediately on the `sync` connection** — so the job stamps `room_closed_at` inside the join itself, and `joinWindowCovers()` returns false from then on. It cost two green-looking failures whose message («Expected 200 but received 403») names the assertion and not the cause. Fake the timeline job ALONE: a bare `Queue::fake()` swallows the billing listener and turns half the charge assertions into confident claims about an empty table.
- **A guard that greps source must strip comments first, or it fails on the rule written beside the code.** `TrustScoreJobIsolationTest` did a raw `str_contains` for `WorkspaceContext::set` across every `Modules/*/Jobs/` file — and four jobs carry a line saying «NEVER `WorkspaceContext::set()`», documenting the very absence the test exists to prove. A red build over an explanation teaches people to delete the explanation. `ContextIsolationTest` had already written the stripper; both use it now. Same family as `theme-tokens.test.ts`, which strips comments before scanning because every fix it guards is written down beside the class it removed.
- **`WorkspaceContext::forget()` PINS THE CONTEXT TO NULL — IT DOES NOT UNRESOLVE IT — AND THAT IS WHY NO TEST IN THIS TREE COULD SEE THE DEFECT ABOVE.** It writes `resolved = true` with `resolvedId = null`, so every later `id()` answers null whatever the user's `users.last_workspace_id` says. A fixture that calls it is therefore measuring a person production never produces: the real request starts with a fresh container, resolves the column, and the scope bites. `CourseWaitlistTest` called it in `beforeEach` and its eight cases called the Action directly — two independent reasons the 404 was invisible, either one sufficient. The spelling that restores «not yet resolved» is `app()->forgetInstance(WorkspaceContext::class)` after `Sanctum::actingAs()`. ⚠️ **And the stamped-student fixture has a second trap inside it**: `last_workspace_id` is in `User::$guarded`, so `User::factory()->create(['last_workspace_id' => $id])` **drops it in silence** and builds the null-context student again — the case then passes against the broken build and reads as a guard. `forceFill()` is the only form that stamps it. Both traps were found by deleting the fix and re-running, never by reading the assertions.
- **`pest --parallel` creates NO database here, and the guard is the framework's not ours — but every DB-touching line in it is inside one `if`.** `Illuminate\Testing\Concerns\TestDatabases` wraps all three of its callbacks (`setUpProcess` drop, `setUpTestCase` create-and-switch, `tearDownProcess` drop) in `whenNotUsingInMemoryDatabase()`, which returns without calling anything when `DB::getConfig('database') === ':memory:'` — which `phpunit.xml` has set since 001. So each worker gets its own in-memory database that dies with the process: no file, no `test_db_1`, and nothing that can reach a developer's `database/database.sqlite` (verified by hashing it across six parallel runs). ⚠️ **What parallel DOES expose is code that only ever ran one file per process.** paratest loads several test files into one worker, so two things that were invisible became fatal: a no-op `use DomainException;` in a namespace-less test file (PHP warns «has no effect»; the loader turns the warning into an error) — 26 files — and one constant defined in two files with different values (`DRAFT_SENTINEL`). ⚠️ **And the no-op rule is about the FILE, not the line**: `tests/Support/*` DO declare a namespace, so their identical-looking `use ZipArchive;` is load-bearing — deleting it cost eleven tests with `Class "Tests\Support\ZipArchive" not found`. `Storage::fake` still shares one root across workers (61 calls in 36 files) and has not collided in any full run; it is the first place to look if the suite ever goes flaky.
- **The hook that seeds reference data once per process is `$seeder`, NEVER `afterRefreshingDatabase()` — and the wrong one looks exactly like the right one.** `RefreshDatabase::refreshDatabase()` calls `refreshTestDatabase()` (which migrates once, then `beginDatabaseTransaction()`) and only THEN `afterRefreshingDatabase()` — so seeding there happens INSIDE each test's transaction, is rolled back with it, and is re-run for every test: the state you were trying to leave, wearing the shape of a fix. `protected $seeder = TestCatalogueSeeder::class` on `Tests\TestCase` is read by `migrateFreshUsing()` and passed to `migrate:fresh --seeder=…` inside `migrateDatabases()`, before any transaction exists. ⚠️ **And that ordering is also why a test may still edit a catalogue**: five files run `GamificationAction::query()->update(['daily_cap' => null])` in `beforeEach` and `RegistersFakeChannels` writes `message_templates` — all inside the per-test transaction, all rolled back, no leak. The five catalogues cost 181 queries × 2912 tests ≈ 527,000 queries as a `beforeEach`; the reason each one must exist is written beside its `call()` in that seeder and must move with it.
- **The three slowest tests are 5.5% of the suite and their numbers are NOT negotiable.** `LedgerEqualityTest` (10,000 awards, 87 s), `LedgerInvariantTest` (10,000 movements, 45 s) and `ExportScaleTest` (50,000 rows, 9 s). Cutting the loops to 500 was proposed here and withdrawn: `LedgerInvariantTest`'s own docblock says «The number is the spec's» — 10,000 is `SC-001`'s figure, `ExportScaleTest`'s N is the whole point of «without holding them», and an assertion weakened to finish sooner is a green gate over a smaller measurement. `->group('slow')` marks them and **nothing excludes it, deliberately**: it is a description, not a gate. What moves them off the critical path is CI sharding — they land in one shard of four and the other three run beside them, with nothing dropped from the merge gate.
- **A query budget needs warming until STEADY, and one warm-up request is not that.** `QueryBudgetTest`'s presence-endpoint case asserts `<= 15`; it failed once with **16** in eight full parallel runs and passed on an identical re-run. ⚠️ **The cause was measured, not guessed** — sixty consecutive pings inside one test showed the steady state is **14** while the request straight after a single warm-up costs 15 or 16, and the difference is `select * from "platform_settings" where "key" = ?`: an operational number cached after its first read (this tree keeps those in rows, never in `config/`). One request does not touch every key the path reads, because creating the attendance row and updating it are different branches reading different settings; the second does. The fix is a **second warm-up request**. ⚠️ **The ceiling was NOT raised to 16, and must not be**: the regression this budget exists to catch is worth TWO queries — the balances fetched twice per beat, once by the withholding check and once by the prepaid fall-through — so 16 over a steady 14 readmits it with room to spare. Warming until steady makes the measurement honest; loosening the number would have made it quiet. The general rule: **when a budget flakes by one, find the query, do not move the line.**
- **`RefreshDatabase` on `Unit` makes every pure-function test pay for a migration.** `tests/Pest.php` granted it `->in('Feature', 'Unit')`, so `PhoneNumberTest` — whose own comment says «nothing here touches a database» — was billed for one; the suite's fastest possible test is 10 ms and its median is 706 ms. It is `->in('Feature')` now, and the two Unit files that genuinely need a database declare `uses(RefreshDatabase::class)` themselves: `MinorUnitsTest` (money's round trip through real tables) and `CostPlusPricingTest` (`PlatformSettings` is rows in `platform_settings`, per this file's own rule that operational numbers live there and not in `config/`). Six of the eight need nothing. ⚠️ The saving is small; the point is that a Unit test needing a database now has to say so, and one that says so is either declaring a real dependency or is a Feature test in the wrong folder.
- **A Pest helper is a GLOBAL function, so two test files may not spell one name differently.** `relateGuardian()` was declared in `Payments/TeacherNeverBuysTest.php` and in `LiveSessions/ChildScheduleGuardTest.php` with **different signatures** — invisible while each file gets its own process, and a fatal «Cannot redeclare function» the moment one worker loads both, which is every `pest --parallel` run and any invocation naming the two directories together. Same family as the `DRAFT_SENTINEL` collision above, reached through a function instead of a constant: **name a file-local Pest helper after what that file is about**, not after the domain noun. ⚠️ **And the check is `php vendor/bin/pest --list-tests`, which loads every file into ONE process in about a second** — spec 038 shipped a `sweep()` that collided with `RecordingRetryTest`'s, and four green targeted runs could not see it because each one got a process of its own. It is the cheapest gate in the repository and the only local one that reaches this class.
- **A SEQUENTIAL TEST OF AN ATOMIC CLAIM IS GREEN AGAINST A BUILD WITH NO CLAIM IN IT — measured again in 034's waitlist.** `InviteFromWaitlist` reads the first N un-invited rows and then claims each with `UPDATE … WHERE invited_at IS NULL`, because two officers opening two groups at once read the same list and would invite the same people twice while the next in line is never invited. The obvious test — «invite, then invite again» — passes with the condition deleted, because the *candidate query* already excludes invited rows, so no row is ever read twice. The window is between the `get()` and the per-row `UPDATE`, and it is opened single-threaded with a **model `retrieved` hook** that performs the competing write from inside `get()` itself: that IS the other runner winning in exactly that instant, no threads and no sleeps — the same trick `onCreateRoom` and `onRecording` already use here. Deleting the condition then fails with «Failed asserting that 1 is identical to 0». The rule generalises: **when a claim's guard is a condition the surrounding query also enforces, the sequential test proves nothing — find the seam and write the competing write into it.**
- **A COUNTER, A LOG LINE AND A GREEN JOB EACH PROVE A NARROWER THING THAN THEY LOOK LIKE, AND THE DIFFERENCE IS WHERE THEY SIT RELATIVE TO THE `try`.** Spec 038's production verification claimed that `retention_sweep_runs.categories_processed` rising 19→21 showed the two new arms had executed. It does not: `$processed++` sits **above** `RunRetentionSweepJob`'s `catch (Throwable)`, so the counter reads 21 identically had both arms thrown. What it *does* prove is worth having and is a different fact — that `PersonalDataRegistry::forCategory()` resolved an owner for both keys, i.e. the orphan check `PersonalDataContractCoverageTest` exists for. The no-throw evidence is `findings_count = 0` alone, and even that covers the discovery SELECT only: with zero candidates no `UPDATE`, no tombstone and no `INSERT` ran. **Before citing a number as evidence, read where it is written relative to the error handling, and say which half of the claim it carries.** The mirror is the cap job, where the claim IS sound: `Log::info('identity.auth_session_cap.swept', …)` is the last statement of `handle()`, so its presence proves the grouped query above it ran on real MySQL. ⚠️ **AND A JOB RUN TWICE AND COMPARED PROVES NOTHING ABOUT ORDERING.** The SC-006 case ran the cap job, snapshotted, ran it again and asserted the id set was unchanged — but by the second run nobody is over the cap, so nothing is deleted and the comparison is the post-run state against itself; deleting `orderByDesc('id')` left all nine cases green. A database is deterministic for one query over one dataset, so **two identical runs agree with no tiebreak at all**. The test that bites NAMES which of two tied rows must survive. ⛔ **AND AN OWNER'S DECISION THAT COMPILES DOWN TO ONE TERNARY NEEDS ITS OWN TEST, WITH BOTH HALVES.** «`ip_hash` goes to the account holder alone» became `$ownRequest ? ['ip_hash' => …] : []` in `IdentityPersonalData::export()` and was guarded by nothing — `ExportFieldAllowlist` deliberately does not ban the key, so deleting the ternary left the whole suite green while every guardian-opened archive gained a child's location history. Both halves are required: «the guardian's row has no `ip_hash`» is vacuously true of an arm that yields the guardian nothing, so each case asserts the ROW IS PRESENT first. ⚠️ **And when a contract's docblock states a safety property its only in-tree caller does not implement, fix the caller.** `LegalHoldDirectory` says a hold «is asked before every batch, never once at the top of a run» and `EloquentLegalHoldDirectory` refuses to memoise on that premise — while `RunRetentionSweepJob` resolved the list once above the category loop and handed the same array to every batch of every category. Weakening the contract to match the weaker caller is the wrong direction for an irreversible walk; the cap job proves it is implementable.
