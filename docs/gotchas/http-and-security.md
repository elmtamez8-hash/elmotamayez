# Gotchas — HTTP surface, rate limits and proxies

Moved verbatim from `CLAUDE.md` (the rule headlines stay there). Read this file before changing routes, middleware, rate limiters, API response shapes, logging. Bullets that say «above» may now point into another file in `docs/gotchas/`.

- **Rate limiters are named** (`throttle:auth` · `throttle:registration` · `throttle:public`, defined in `AppServiceProvider::registerRateLimiters()`). Inline `throttle:5,1` is banned: `ThrottleRequests` keys guests on `domain|ip` with no route in the hash, so every inline limit shares one counter and the strictest one wins — browsing the marketplace used to lock a visitor out of logging in.
- **`$exception->getMessage()` in a log line is a leak, and `QueryException` is the ordinary case rather than the exotic one.** Laravel interpolates the BINDINGS into a query exception's message, so any failing statement inside the export or erasure walk carries whatever it was searching for — an address, a phone number, a name — into a line that ships straight to a monitoring vendor. `FulfilDataRequestJob` logs the exception **class**; nothing is lost, because the job rethrows and the full message and trace land in `failed_jobs.exception`, in our own database. That is the whole line FR-041 draws: the operational log leaves the building, the failure table does not. Found by `LogHygieneTest`, which captures `MessageLogged` rather than reading a file — the test environment writes nowhere, so a file-based assertion would be asserting that an empty file contains no names — and asserts on **ASCII sentinels**, because log context and queue payloads are JSON and an Arabic needle is `\u`-escaped and vacuously absent.
- **`TRUSTED_PROXIES=*` DOES NOT MEAN «trust the proxy that called you» — it writes `['0.0.0.0/0', '::/0']`, and the method that does it is named `setTrustedProxyIpAddressesToTheCallingIp()`.** Read the assignment, never the method name: `vendor/laravel/framework/src/Illuminate/Http/Middleware/TrustProxies.php:118` is one line and it trusts every address in IPv4 and IPv6 — the `AccessToken::$ttl` family, where a vendor's own wording said one thing and the code beneath it said another. `AppServiceProvider::trustConfiguredProxies()` has said «never `'*'`» in its docblock since it was written, and a deployment still shipped it, which is why the MECHANISM is recorded here and not only the rule. ⚠️ **The half that makes it exploitable is our own nginx**: `docker/nginx.prod.conf:142` sets `X-Forwarded-For $proxy_add_x_forwarded_for`, and «add» means it **appends** the real peer to whatever the client already sent rather than replacing it — so a forged value survives as the LEFTMOST entry, and Symfony, walking the chain right-to-left past every trusted address, stops on it. Measured 2026-09-03 with a real client `41.200.1.7` that sent `9.9.9.9`: `*` ⇒ `$request->ip()` is **`9.9.9.9`**, `172.16.0.0/12` ⇒ `41.200.1.7`, unset ⇒ `172.18.0.5` (the nginx container). What that costs is not one field: **nine rate limiters** in `AppServiceProvider` key on `ip:` (`auth`, `registration`, `public` and six more), so every limit on the platform is bypassed by rotating a header — unlimited password attempts, unlimited registrations; `terms_consents.ip_address` becomes attacker-supplied, and its own migration says `TrustProxies` must be configured before the column means anything — **a forged address is worse than an honest wrong one, because it looks like evidence in the dispute it exists for**; the same for the IP stamped on a payment receipt and on an approval, and for `StartAuthSession.ip_hash` behind the new-device alert; and `Payments\Http\Middleware\VerifyWebhookSource` — an IP ALLOWLIST guarding the payment webhook — stops being a guard and becomes a door, because the gateway's address is now something the caller types. ⚠️ **And unsetting it is the opposite error, not the fix**: with nothing trusted every person on the platform resolves to the one proxy address, so a five-per-person limit becomes five for everybody at once, and `X-Forwarded-Proto` is ignored too — the app decides it is on `http` and generates signed URLs and redirects with the wrong scheme. The correct value trusts exactly the one proxy that exists: the docker bridge range (`172.16.0.0/12`, or the subnet pinned explicitly in `docker-compose.prod.yml`), which is safe precisely because the `backend` service publishes **no `ports:`** — nginx alone is on 80/443, so nothing outside the internal network can present itself as a proxy. A second proxy in front (Cloudflare, another balancer) grows that list; it never returns to `*`.
- **The `api` middleware group had NO default limiter, so a route that named none carried none.** `bootstrap/app.php` called `statefulApi()` and `appendToGroup()` and never `throttleApi()` — which left every write in Tenancy (create a workspace, invite, accept, remove a member) and the whole of Analytics unbounded, and sharpest `GET /workspaces/invitations/{token}`: unauthenticated, hits the database, answers with the INVITEE'S EMAIL, one line under a route that does carry `throttle:public`. The named limiters are still where the thinking happens — an inline `throttle:n,m` shares one counter with every other inline limit in the app — but the group default is the floor under the routes nobody remembered, so the next one added starts guarded instead of open. It is deliberately far looser than anything the product does (the busiest authenticated caller is a presence heartbeat at two a minute against its own limiter of 240): **a floor that bites a real flow is a floor somebody raises to infinity a week later.** ⚠️ Asserting it needs the GROUP — `$route->gatherMiddleware()` returns the unexpanded name `api`, so a per-route assertion passes against a group with nothing in it.
- **`response()->json(Resource::collection($paginator))` NEVER CALLS `toResponse()`**, so `links` and `meta` are dropped in silence and every reader is stuck on page one with nothing saying there is a page two. The correct form is `->response()->getData(true)`. ⚠️ Fixing it CHANGES THE RESPONSE SHAPE — a bare array becomes `{data, links, meta}` — so the existing assertions move from `0.title` to `data.0.title`, and any client indexing the top level breaks. Check the callers before fixing: `/cms/articles` had none. ⚠️ **AND THE MEASURED CASE IS WORSE THAN «no pagination»: `/enrollments` DROPPED THE WHOLE ENVELOPE AND EVERY READER SHOWED ZERO.** The top-level keys were `[0]` — a bare array — while `/certificates` beside it answered `{data, links, meta}`; and all FOUR readers in `frontend/src` do `res.data ?? []`, which on an array is `undefined`. So «تعلّمي» was empty, the credit-purchase course picker was empty and the dashboard counted 0 — **for every student on the platform, with no error anywhere and every reader written correctly**. The server alone was wrong, so the fix was one line and no client changed. ⚠️ **What let it live was that the index had ZERO tests, of any kind** — an endpoint nothing asserts is an endpoint whose shape is whatever the first person typed, and `->response()->getData(true)` and the broken form are one character apart on the screen. Write the shape test with the fix. ⚠️ **AND IT WAS NOT ONE ENDPOINT — `GET /exams` had the identical line**, found while shipping spec 026: all THREE readers in `frontend/src` write `res.data ?? []`, so the student's «الاختبارات» screen said «لا اختبارات متاحة الآن», the course page's exams tab was empty, and `/manage/exams` told a teacher they had never written a paper. Every exam list in the product, empty. ⚠️ **Its component test mocked `{ data: [...] }`** — i.e. the shape the server never sent — so the frontend suite was green over it too: each half correct on its own, the defect living only in the seam. **When you fix one of these, grep the whole tree for `json(` wrapping a `Resource::collection` of a paginator, rather than fixing the one you tripped over.**
