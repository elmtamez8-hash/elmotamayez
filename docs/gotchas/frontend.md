# Gotchas — Frontend

Moved verbatim from `CLAUDE.md` (the rule headlines stay there). Read this file before changing anything under `frontend/src/`. Bullets that say «above» may now point into another file in `docs/gotchas/`.

- Frontend stores the Sanctum token in `localStorage` and sends `Authorization: Bearer` (`frontend/src/lib/api.ts`); it relies on the Next.js rewrite, so the backend must be running on :8000.
- Don't run `npm run build` while `npm run dev` is up — both write `.next/`, and the dev server then dies with `Cannot find module './NNN.js'`. Stop dev first (or accept that you must `rm -rf .next` and restart it).
- **The frontend is Arabic-only and RTL-only** (spec 002). One root layout, `frontend/src/app/layout.tsx`, declares `lang="ar" dir="rtl"`, loads Cairo, and runs the pre-paint theme script; `(public)` and `(app)` are nested layouts that add chrome only. Adding a second `<html>` anywhere re-splits the product.
- **Colours come from `@theme` in `globals.css`, never from a class.** No `bg-gray-*`, no `bg-white`, no hex in a component. `text-white` is allowed *only* as the foreground of `bg-primary`/`bg-secondary`/`bg-danger`; `accent` and `trust-medium` have their own `-foreground` tokens because white fails 4.5:1 on them. Layout uses logical properties (`ms-*`, `start-*`, `text-start`) — never `ml-*`/`left-*`. Direction lives in icon *names* (`ChevronStartIcon`), not in a CSS flip.
- **Shared UI lives in `frontend/src/components/ui/`** (`Button`, `Card`, `Badge`, `Alert`, `Table`, the `Field` family, `states/`). Components there take no free-form `className` — appearance is a closed set of variants. `components/marketplace/` is now marketplace-specific only. Arabic status labels, money/date formatting **and counted nouns** go through `src/lib/labels.ts`.
- **An Arabic counted noun goes through `counted()`, never a template literal — «٢ مدرّس متاح» shipped to the live marketplace and was reported.** Arabic agrees the noun AND its adjective in five bands, so `${n} مدرّس متاح` is wrong at 2 (مدرّسان متاحان) and at 3–10 (٣ مدرّسين متاحين) and accidentally right at 11. It was **twenty-five sites in thirteen files**, five of which had each written their own half-rule (`if (count <= 10)`) — five spellings of one rule. ⚠️ **The bands come from `Intl.PluralRules("ar")`, not from a hand-written `n <= 10` chain**: CLDR decides the band by the LAST TWO DIGITS, so 103 is `few` while 111 is `many` — a hand-rolled ladder agrees below 100 and diverges above it, which is exactly where nobody tests. ⚠️ **The numeral is the helper's decision, not the caller's**: one and two carry no numeral (Arabic holds the count in the word; «٢ مدرّسان» is a stutter), everything else is prefixed, and `toLocaleString("ar-QA")` lives inside the helper rather than at every call site. ⚠️ **And `other` is REQUIRED rather than defaulting to `one`** — three callers write «حصة واحدة» · «درس واحد» · «طالب واحد», and «واحد» is the standalone singular that cannot follow a numeral, so the default printed «١٠٠ طالب واحد»: worse than the template literal it replaced, which got that one band right. Required, `tsc` names every site. `zero` still defaults (`لا ` + the plural) because `few` is a bare plural everywhere — but it is a DECISION per site: «لا ساعات» on a course whose duration was never measured is a lie, so that one stays «—», and «لا سنوات خبرة» on a teacher in their first year is a verdict on a marketplace card, so it is «أقل من سنة خبرة».
- **Never show a raw error to the user.** 422 goes through `fieldErrors()` and lands under its field; everything else goes through `userMessage()` in `src/lib/errors.ts`. Validation text itself is Arabic from `backend/lang/ar/`, and every new `FormRequest` field needs an entry in that file's `attributes` array or it renders as `phone_number`.
- **A 500 on EVERY page is two route files resolving to one path, and route groups produce no URL segment.** `(app)/(shell)/privacy/page.tsx` and `(public)/privacy/page.tsx` both answer `/privacy` — the nested layouts do NOT keep them apart, whatever a comment says — and Next refuses to serve the **whole application**, not just those two: `/`, `/login`, `/dashboard`, all 500 with `You cannot have two parallel pages that resolve to the same path`. It shipped and sat for a session because neither `npx tsc --noEmit` nor `npm test` builds routes, and the message names the two files while the symptom is global. The in-app screen is `/settings/privacy` now; `/privacy` belongs to the public policy, which is linked from every footer and both signup forms. ⚠️ **And the dev server does not recover on its own** — it holds the stale build manifest and keeps printing the old error after the file moves. Restart it.
- **The BROWSER serves the stale chunk, and restarting the dev server does not clear it — only a hard reload does.** Measured three times on 2026-09-06: a saved page change was invisible through a normal reload, through a `?v=2` cache-buster, through a dev-server restart AND through deleting `.next` — and appeared instantly on `Ctrl+Shift+R`. This is a different failure from the stale build manifest below it: there the SERVER is wrong, here the server is right and the client is holding the old JavaScript. The tell is that the served HTML/JSON is correct when you `curl` it while the page still shows the old behaviour. ⚠️ **The sharpest form of it is self-inflicted**: temporarily editing a source file to prove a test bites — reverting a fix, running the suite, restoring it — is compiled by the running dev server and can be cached by whoever has the page open, so the user hits a crash from a version that no longer exists on disk. Verify the disk before believing a stack trace, exactly as `failed_jobs` traces are checked against `git log`; and prefer proving the bite with `git stash` on a file nobody is looking at, or say what you are about to break.
- **A 500 on one page with a `Jest worker … exceeding retry limit` message is a corrupted `.next/`, not a bug in that page.** Delete the directory and restart. The two axe violations it produces (`document-title`, `html-has-lang`) are Next's error page being audited instead of yours, which reads as an accessibility regression on a page nobody touched.
- **A swallowed error is worse than a raw one.** `.catch(() => undefined)` on the lesson fetch rendered a permanently blank page whenever the item was not the viewer's — the reason sitting unread in the response. The rule against showing raw errors is not a rule for showing nothing; `userMessage()` is what turns one into a sentence.
- **A destructive control that cannot be taken back gets `ConfirmButton`, and it is a two-press ARM rather than a dialog.** «اكتم الجميع» and «أخرِج الجميع» sit in one wrapping row eight pixels apart at a 40px target on a teacher's phone, as do the per-row «كتم» and «إخراج» — one of each pair is undone in a tap and the other ejects a paying student mid-lesson; «إنهاء الحصة» closed the broadcast for everybody in one press, unreopenably. ⚠️ **THERE IS A MODAL IN `components/ui/` SINCE SPEC 033, AND `ConfirmButton` IS STILL RIGHT HERE — the reason changed, the answer did not.** The old reason was the cost of building one (a focus trap, a scroll lock and an escape handler for a one-word question); `Modal` is a native `<dialog>` opened with `showModal()`, so the platform pays all three. The reason now is WHEN these controls are pressed: mid-lesson, where a window covering the screen is the same harm as the `window.confirm` it replaced — a teacher cannot watch the class while answering a dialog. **The line is the moment, not the severity**: a window belongs on a question asked while nothing else is happening (deleting a chapter, changing an item's type — spec 033 moved all four of those), and a two-press arm belongs on a control pressed during a live lesson. `window.confirm` itself is gone from the tree entirely and `src/lib/no-native-dialogs.test.ts` fails the build if it returns; it was untranslated on some Arabic Android builds and froze the page mid-lesson. The button becomes the question, and the **disarm timer is the load-bearing half**: without it a half-pressed control lies in wait and the next stray tap fires it. ⚠️ Its test must use `fireEvent`, not `userEvent` — the latter awaits real timers between its simulated steps, so under `useFakeTimers` it hangs on a clock nothing advances and the test TIMES OUT rather than failing.
- **⚠️ EVERYTHING WRITTEN IN `globals.css` OUTSIDE `@theme` IS **UNLAYERED**, AND UNLAYERED CSS BEATS EVERY `@layer` — INCLUDING THE `utilities` LAYER TAILWIND v4 PUTS ITS CLASSES IN.** So a plain element rule there silently overrides the same property's utility on every element of that kind, at any specificity, with no warning and nothing in a diff to see. Spec 033 paid for it twice in one screen: a `dialog { max-width: none }` reset beat `max-w-md` and the modal opened full width pinned to the top of the viewport with its title above the fold; the fix for THAT left `background: transparent`, which beat `bg-surface-raised` and produced a card the page could be read through. ⚠️ **And the reset was never needed**: author styles beat UA styles whatever the layer, so `p-6` and `border-line` on the element already win — the only property that genuinely had to be written was `margin: auto`, because Tailwind's own preflight resets `margin: 0` on `*` and that is exactly the third of the three declarations (`position: fixed; inset: 0; margin: auto`) a `dialog:modal` is centred by. The rule: **name a property in a bare element rule here only when NO utility sets it and something else has taken it away** — and say which, beside it. ⚠️ **No component test can see any of this**: jsdom has no layout and no cascade to speak of, and all 30 `Modal` assertions were green over both broken versions. It was found by opening the screen.
- **A colour class naming a token `@theme` never defined paints NOTHING, silently — and it has now shipped three times.** Tailwind v4 emits no rule for an undefined token, so `bg-success` / `border-success` / `text-success-ink` were present, correct-looking, and invisible: an 8px transparent dot for «who is speaking», an ink-coloured ring where a green one was meant, and «إجابة معتمَدة» in body text. There is no `success` token — the tone name exists only in `TONE_CLASSES`, which maps it to `bg-secondary/15 text-secondary-ink`. Its own test passed by asserting the `aria-label` over an unpainted mark, which is the family this file records under «green for the wrong condition». `src/lib/theme-tokens.test.ts` reads the tokens OUT of `globals.css` rather than carrying a list (a second list is a second answer that ages at the first token anyone adds) and **strips comments before scanning**, because every one of the three fixes is written down beside the class it removed. ⚠️ And `TONE_CLASSES.warning` was `text-accent-foreground` — white, earned against the SOLID brass fill and roughly 1.3:1 over a 20% tint, carrying the confused count, the two-seats-left badge and the grading count.
- **⚠️ `bg-surface-muted` IS THE FOURTH UNDEFINED COLOUR TOKEN TO SHIP, and `LessonRow` had written the rule down one directory away.** There is no `surface-muted` in `@theme` — Tailwind v4 emits no rule for a token it has never seen — so every avatar with no photo has been a transparent circle with a letter floating in it since the participants list shipped: no error, no warning, nothing in a snapshot. `src/lib/theme-tokens.test.ts` scans for the names that SOUND like ours and it now includes this one; the fix is `bg-primary-soft`. A rule that lives only in a comment is a rule the next file does not read.
- **`PasswordField` is the one spelling, and `"password"` had to leave `TextField`'s type union in the same change.** Left in, `TextField type="password"` stays a second spelling that renders no reveal button, and the two drift screen by screen — which is exactly the shape `NumberField` already solved by ALSO removing `"number"` from that union. Removing it is what makes `tsc` walk every existing call site (fourteen fields, seven files). Three details are load-bearing and each has shipped as a bug somewhere: **`type="button"`** on the toggle (a bare button inside a form defaults to `submit`, so the first press of the eye sends a half-filled registration), **nothing persisted** (a revealed password surviving a reload is a password left on an unattended screen), and an **`aria-label` that follows the state** (the icon says nothing to a screen reader). The browser's own control is hidden in `globals.css` — two adjacent buttons for one job, only one of them ours to name. ⚠️ Its test uses `fireEvent`, not `userEvent`, for the reason `ConfirmButton` already recorded.
- **A screen with no permission gate may only make reads EVERYBODY holds — and `/dashboard` made one nobody but a teacher did.** The landing page after sign-in carries no `permission` in `mainNav` because it is everyone's first screen; its fourth stat card called `/courses`, the AUTHORING index, gated by `CoursePolicy::viewAny()` on the tenant permission `courses.view`. A student is a member of no workspace, so `WorkspaceContext::id()` is null, the spatie team id is null, and **every `can()` below it is false** — 403 for every student and every guardian on the platform. ⚠️ **And the blast radius was the whole page, not the card**: the three good reads share one `Promise.all`, so a single rejection took `/enrollments`, `/certificates` and the entire layout down to «تعذّر تحميل البيانات» — the *correct* error state (FR-018) telling the majority of accounts to check a connection that was never the problem. Same family as `belongsToCurrentWorkspace()` denying on a null context: a permission-shaped question asked of somebody who holds no permissions at all. The replacement is `/marketplace/courses?per_page=1` read for **`meta.total`**, not `data.length` — the old call was paginated fifteen at a time, so even for a teacher the card stopped counting at 15. ⚠️ It was invisible to every suite: the backend answers each endpoint correctly in isolation, `tsc` and Playwright's authenticated `storageState` are a teacher, and a component test whose fake resolves every path proves nothing about **which** path was asked. `dashboard/page.test.tsx` asserts on the CALL LIST and rejects everything else the way the server does.
- **AN ENDPOINT NO FILE IN `frontend/src` CALLS IS A FEATURE NOBODY HAS — and three of them surfaced in one day (2026-09-06), each reported by the user as a missing product.** The backend was complete every time: `POST /settlement/rate-requests` (a teacher asking to change their price) had its Action, its limiter, its policy, two refusal rules AND `settlement.requestRate` already written in `lib/settlement.ts` — with the screen that should host it printing «تواصل مع إدارة المنصة», a support ticket standing in for a built route. `PUT /teacher/availability` did not exist but `SetAvailability` did, written once at signup, so `availability_slots` had four readers and a write-once writer. And `POST /enrollments/{e}/lessons/{l}/complete` has existed since 016 while **nothing in the tree calls it**, so no video and no article can ever be completed: `progress_pct` is stuck at 0, `CourseCompleted` never fires, and **no certificate has ever been issuable** — the forever-capped defect this file already records, reached not through a broken item but through an absent control. ⚠️ **The tell is a comment describing a caller that does not exist**: `lessonPayload`'s `enrollment_uuid` says in as many words «the field is what a student's screen uses to mark an item complete», and `PublicProfileUrlCard` documented a 403 that was never implemented. **A grep from the endpoint back to `frontend/src` is the check** — `tsc`, pest and vitest are all green on a route with no caller, because each half is correct on its own. ⚠️ **And when the screen is finally written, the DOOR needs the guard too**: hiding a control is not a guard. `completeLesson` accepted an **exam** item from any enrolled student — one request to declare a paper passed and move the percentage without answering a question — so the refusal is in the controller (not the Action, which `CompleteExamLessonOnSubmission` legitimately shares) and reads `LessonTypeRegistry::isSelfCompletable()`, the same predicate the payload flag reads. ⚠️ **`assignment` is deliberately self-completable against the tidy symmetry**: measured, `AssignmentSubmitted` has ONE listener and it sends a notification — nothing completes an assignment lesson — so grouping it with `exam` because both are `FAMILY_REFERENCE` would make every assignment permanently incompletable, i.e. the worst defect in this file, created by the fix for a smaller one.
- **A session, booking or schedule time is drawn on `useViewerTimeZone()`, never on `session.timezone` (2026-09-25).** The product has users in Qatar and Egypt, and Egypt observes DST; `session.timezone` on the resources is the PLATFORM zone, kept for compatibility only. The hook (`lib/viewer-time-zone.ts`) is the account's stored zone, else the browser's, and works in leaf components rendered with no `AuthProvider`; `formatSession*` stay pure and take the zone as an argument, and a typed session time goes through `localDateTimeToIso(value, zone)` so it is read on the clock it is shown back on. Where two countries read one time (private requests, reschedules) use `formatSessionTimeWithZone`. Weekly availability is wall-clock + zone — convert with `lib/availability.ts`, never by hand.
