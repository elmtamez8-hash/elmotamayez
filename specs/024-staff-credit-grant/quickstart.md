# Quickstart — التحقّقُ من منحِ الاشتراكِ بيدِ الموظّف

دليلُ تشغيلٍ وتحقّق. التفاصيلُ في [contracts/staff-credit-grant.md](./contracts/staff-credit-grant.md)
و[data-model.md](./data-model.md) ولا تُكرَّرُ هنا.

---

## المتطلّبات

```bash
cd backend && php artisan migrate      # إضافةُ عمودٍ خالصة — لا migrate:fresh
cd backend && php artisan serve        # :8000 — واللوحةُ على /admin
```

⚠️ **`migrate` لا `migrate:fresh`**: الهجرةُ إضافةُ عمودٍ بلا ردم، و`migrate` وحدَها تُثبِتُ
أنّها تعملُ على قاعدةٍ فيها بياناتٌ — وهو ما سيحدثُ في الإنتاج.

⚠️ **ولا حاجةَ لتشغيلِ `frontend`** في أيٍّ من هذه السيناريوهات: السطحُ كلُّه في `/admin`.
السيناريو ٤ وحدَه يحتاجُه، وهو سيناريو عدمِ الانحدار.

**حسابُ التجربة**: مستخدمٌ في `platform_staff` بدورِ `finance-admin`. ⚠️ ويحتاجُ
`RolesAndPermissionsSeeder` مبذوراً، وإلّا كان الإذنُ اسماً لا يحملُه أحدٌ فردَّت كلُّ شاشة.

## السيناريو ١ — المنحُ لطالبٍ **جديدٍ تماماً** (US1 · SC-009)

هذا هو السيناريو الحاسم؛ الباقي فروعُه.

1. أنشئْ طالباً **بلا تسجيلٍ ولا عضويّةِ مساحةِ عملٍ ولا رصيدٍ سابق** — لا من بذرةٍ ولا من
   `addWorkspaceMember`.
2. من `/admin` ← «منحُ اشتراك»: اختَرْ ذلك الطالب، كورساً منشوراً لمدرّسٍ معتمَدٍ له معدّلٌ
   مقبول، وباقةَ ثمانِ حصص.
3. **قبلَ الحفظ**: يظهرُ المبلغُ المتوقَّع.
4. أرفقِ الإيصالَ واحفظْ.

**المتوقَّع**: طلبٌ **معلَّق**. والقياسُ الحاسمُ فوراً بعدَ الحفظِ وقبلَ الاعتماد:

```bash
cd backend && php artisan tinker --execute="dump(\App\Modules\Payments\Models\CreditBalance::withoutWorkspaceScope()->where('student_user_id', <ID>)->get(['remaining_credits','purchased_credits'])->toArray());"
```

**المتوقَّع**: **صفر · صفر** (FR-003 · SC-003). رقمٌ غيرُ الصفرِ هنا يعني أنّ الميزةَ تسكُّ
على النيّة.

ثمّ اعتمدْ من شاشةِ الطلباتِ وأعِدِ القراءة ⇒ **٨ · ٨** على ذلك الكورسِ وحدَه.

⚠️ **ولا وصولَ إلى محتوى الكورس**: المنحُ لا يُنشئُ تسجيلاً (FR-004أ).

```bash
cd backend && php artisan tinker --execute="dump(\App\Modules\Learning\Models\Enrollment::withoutWorkspaceScope()->where('student_user_id', <ID>)->count());"
```

**المتوقَّع**: **صفر**.

## السيناريو ٢ — ما يجبُ أن يُرفَض (FR-005 · FR-013)

| المُدخَل | المتوقَّع |
|---|---|
| الطالبُ المختارُ هو **المدرّسُ** في ذلك الكورس | **يُرفَض** — التخطّي لا يشملُ رفضَ البائع |
| حسابٌ لا يحملُ `billing.purchase.approve` يفتحُ الشاشة | يُردّ، **ولا يرى رابطَها في التنقّلِ أصلاً** |
| مالكُ مساحةِ العملِ (‏أعلى دورِ مستأجر) | يُردّ — ولا يدخلُ اللوحةَ من الأساس |
| باقةٌ عُطِّلَت بينَ فتحِ الشاشةِ والحفظ | يُرفَضُ الحفظُ برسالةِ «هذه الحزمةُ لم تعدْ متاحة» |
| كورسٌ لمدرّسٍ بلا معدّلٍ معتمَد | لا باقاتٍ تُعرَض — **قبلَ** الحفظِ لا بعدَه |

⚠️ **واختبرِ الاتّجاهَين**: «من يحملُه ينجح» لا يقلُّ لزوماً عن «من لا يحملُه يُردّ». إذنٌ
يُصنَّفُ بالغيابِ يمرُّ كلَّ اختباراتِه ويحرسُ صفراً — سابقةُ `taxonomy.manage` في ٠٠٩ —
لأنّ Laravel يفشلُ **مفتوحاً** إلى «لا سياسةَ تنطبق».

## السيناريو ٣ — ⚠️ الموظّفُ الذي يملكُ مساحةَ عمل (R6 · SC-006)

**هذا السيناريو هو الذي لا تراه تجهيزةٌ بمساحةٍ واحدة.**

1. اجعلْ موظّفَ الماليةِ يملكُ `last_workspace_id` غيرَ فارغ (‏مساحةُ عملٍ خاصّةٌ به).
2. امنحْ لطالبٍ على كورسٍ في **مساحةِ عملٍ أخرى**.
3. افتحِ الطلبَ واعتمدْه.

**المتوقَّع**: **٢٠٠ في الخطوتَين**. قبلَ الإصلاح: **٤٠٣** بلا سببٍ يُذكَرُ على الشاشة —
لأنّ «سياقاً محلولاً لا يطابقُ يبقى رفضاً».

**وأعِدْها بموظّفٍ بلا مساحةِ عمل** ⇒ ٢٠٠ أيضاً. الحالتانِ معاً هما الاختبار؛ الثانيةُ
وحدَها تمرُّ خضراءَ فوقَ العطل.

## السيناريو ٤ — مسارُ الطالبِ لم يتغيّرْ (US3 · SC-008)

```bash
cd backend && php vendor/bin/pest tests/Feature/Payments
```

**المتوقَّع**: خضراءُ كلُّها، **وصفرُ ملفِّ اختبارٍ عُدِّل**. أيُّ توكيدٍ قائمٍ احتاجَ تعديلاً
يعني أنّ الوسيطَ لم يكنِ افتراضيّاً حقّاً.

## السيناريو ٥ — السجلُّ يفرّقُ بين الدورَين (FR-008ب · SC-010)

بعدَ منحٍ أنشأه الموظّفُ نفسُه واعتمدَه:

```bash
cd backend && php artisan tinker --execute="dump(\App\Modules\Payments\Models\Order::withoutWorkspaceScope()->latest()->first(['user_id','granted_by','approved_by'])->toArray());"
```

**المتوقَّع**: ثلاثةُ حقول — الطالبُ في الأوّل، والموظّفُ في الأخيرَين **معاً**. قيمةٌ فارغةٌ
في `granted_by` بعدَ منحٍ تعني أنّ العمودَ خارجَ `$fillable` ولم يُكتَبْ بـ`forceFill`،
والاستجابةُ لن تكشفَ ذلك — **اقرأِ الصفَّ لا الردّ**.

وأعِدْها بعدَ **شراءِ طالبٍ بنفسِه** ⇒ `granted_by` **فارغ**. الاتّجاهانِ معاً، وإلّا مرَّ
تنفيذٌ يختمُ الموظّفَ على كلِّ طلبٍ في المنصّة.

## البوّابات — دفعةً واحدةً في النهاية

```bash
cd backend && php vendor/bin/pest tests/Feature/Payments
cd backend && ./vendor/bin/pint --test && ./vendor/bin/phpstan analyse
```

⚠️ **لا حزمتَي pest معاً** — تتشاركانِ قرصَ الاختبارِ وتصنعانِ فشلاً كاذباً.
ولا حزمةَ اختباراتٍ محلّيّةً كاملة: CI يشغّلُها؛ يُختبَرُ ما تغيّر، مرّةً واحدة، في النهاية.
`npx tsc --noEmit` غيرُ لازمٍ هنا — صفرُ ملفٍّ في `frontend/`.

## ما لا يُقاسُ هنا — ولا يُدَّعى

- **أنّ الميزةَ تمنعُ احتيالاً داخليّاً.** لا تمنعُه ولا تدّعي: موظّفٌ يحملُ الإذنَ يستطيعُ
  منحَ رصيدٍ بإيصالٍ مزوَّر. ما تفعلُه هو **جعلُ ذلك مقروءاً** — إيصالٌ محفوظ، ومنشئٌ
  ومعتمِدٌ باسمَيهما. الضبطُ بإنسانَين قرارٌ مؤجَّلٌ صراحةً (‏Clarifications · Q2).
- **سلوكُ رفعِ ملفٍ من Filament إلى مجموعةِ وسائطِ الإيصال.** لم يُجرَّبْ بعد؛ تفصيلُ تنفيذٍ
  يُحسَمُ في `tasks.md`.
- **أنّ لا سطحَ آخرَ في المنتَجِ يجمعُ الإنشاءَ والاعتماد.** SC-010 يُقاسُ على ما تضيفُه هذه
  الميزةُ، لا بمشيٍ شاملٍ على الشجرة.
