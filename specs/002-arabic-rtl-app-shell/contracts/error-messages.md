# Contract: رسائل الخطأ (Error Messages)

**Feature**: `002-arabic-rtl-app-shell` · **يحقّق**: `FR-016` · `FR-017` · `FR-018`

من يترجم ماذا وأين. القاعدة الواحدة: **رسالة التحقّق تُترجَم عند مصدرها في Laravel، وما
عداها يُترجَم في الواجهة بحسب رمز الحالة.** لا مطابقة نصوص إنجليزية في أي مكان.

---

## ١ — شكل الاستجابة: ثابت، لا يتغيّر

`NFR-001` يمنع تعديل عقود الخلفية. الشكل يبقى حرفياً كما هو اليوم:

```jsonc
// 422
{ "message": "…", "errors": { "phone_number": ["…"], "email": ["…"] } }

// 4xx / 5xx أخرى
{ "message": "…" }
```

**ما يتغيّر**: محتوى `message` وعناصر `errors` — من الإنجليزية إلى العربية. **ما لا يتغيّر**:
المفاتيح، وتداخلها، ورموز الحالة، وأسماء الحقول (`snake_case` كما هي — هي مفاتيح برمجية
لا نصّ معروض).

---

## ٢ — الطرف الخلفي: `backend/lang/ar/`

### ٢٫١ — الضبط

```
APP_LOCALE=ar
APP_FALLBACK_LOCALE=ar
```

يُحدَّث في `.env.example` و`docker/` و`phpunit.xml`. `APP_FAKER_LOCALE` يبقى `en_US` —
بيانات المصانع ليست نصّاً معروضاً.

### ٢٫٢ — `lang/ar/validation.php`

نسخة عربية من رسائل Laravel القياسية، **زائد** مصفوفة `attributes` — وهي جوهر `FR-016`:

```php
'attributes' => [
    'phone_number'          => 'رقم الهاتف',
    'email'                 => 'البريد الإلكتروني',
    'password'              => 'كلمة المرور',
    'password_confirmation' => 'تأكيد كلمة المرور',
    'first_name'            => 'الاسم الأول',
    'last_name'             => 'اسم العائلة',
    'title'                 => 'العنوان',
    'description'           => 'الوصف',
    'price'                 => 'السعر',
    'workspace_id'          => 'مساحة العمل',
    'course_id'             => 'الكورس',
    // … كل حقل يظهر في FormRequest واحد على الأقل
],
```

فتصير الرسالة «حقل رقم الهاتف مطلوب» تلقائياً، بلا سطر واحد في الواجهة.

**التغطية المُلزِمة**: كل حقل مذكور في أي `FormRequest` تحت `app/Modules/*/Requests/`
**يجب** أن يكون له مدخل. حقل بلا مدخل يظهر باسمه البرمجي — عطل صامت في `FR-016`.

### ٢٫٣ — القاعدة المخصّصة

قاعدة تحقّق مخصّصة تُطلق رسالتها بنفسها **يجب** أن تُطلقها عبر `trans()` بمفتاح تحت
`lang/ar/`. **يُمنع** نصّ حرفي — عربياً كان أو إنجليزياً — داخل `Rule` أو `FormRequest`.

### ٢٫٤ — أثر مُلزِم على البوابة

أي اختبار `pest` يؤكّد نصّ رسالة تحقّق إنجليزياً سيسقط. **يُصلَح في نفس الـ PR** — لا
`skip`، ولا استثناء لغة في بيئة الاختبار. الأفضل أن يؤكّد الاختبار **مفتاح الحقل** في
`errors` لا نصّ الرسالة؛ يُعاد كتابته هكذا حيثما أمكن.

## ٣ — الطرف الأمامي: `src/lib/errors.ts`

خريطة واحدة لما **ليس** خطأ تحقّق. لا تشمل ٤٢٢ إطلاقاً.

```ts
export function userMessage(err: unknown): string
```

| الحالة | الرسالة |
|---|---|
| `401` | «انتهت جلستك. سجّل الدخول من جديد.» |
| `403` | «لا تملك صلاحية لهذا الإجراء.» |
| `404` | «العنصر المطلوب غير موجود أو حُذف.» |
| `409` | «تعذّر إتمام العملية — تغيّرت الحالة. حدّث الصفحة وأعد المحاولة.» |
| `413` | «الملف أكبر من الحدّ المسموح.» |
| `419` | «انتهت صلاحية الطلب. أعد المحاولة.» |
| `429` | «محاولات كثيرة في وقت قصير. انتظر قليلاً ثم أعد المحاولة.» |
| `5xx` | «حدث خطأ لدينا. أعد المحاولة بعد قليل، وإن تكرّر فتواصل مع الدعم.» |
| انقطاع الشبكة | «تعذّر الاتصال. تحقّق من اتصالك بالإنترنت.» |
| غير معروف | الرسالة العامة نفسها + تسجيل الأصل في الكونسول |

**قاعدة مُلزِمة** (`FR-017`): **يُمنع** أن يصل `err.message` الخام إلى الشاشة. الدالة
تُرجع نصّاً من الخريطة أعلاه حصراً. نصّ الاستثناء يبقى متاحاً في الكونسول للمطوّر.

**الاستثناء الوحيد**: `422`. رسالته عربية من المصدر (§٢) وتُعرض كما هي.

## ٤ — مسار العرض

```
┌── 422 ─────────────────────────────────────────────────────────┐
│  fieldErrors(err) → Record<field, message عربية من Laravel>    │
│  المكوّن يمرّرها إلى <Field error={…}> لكل حقل                  │
│  الحقول غير المطابقة لأي حقل في النموذج → تنبيه أعلى النموذج    │
└────────────────────────────────────────────────────────────────┘

┌── ما عداها ────────────────────────────────────────────────────┐
│  userMessage(err) → نصّ عربي من الخريطة                        │
│  قائمة فاشلة  → <Table state="error" onRetry={…}>             │
│  إرسال فاشل   → <Alert tone="danger" title={userMessage(err)}> │
└────────────────────────────────────────────────────────────────┘
```

`fieldErrors()` في `src/lib/api.ts:96` قائمة وتعمل — **لا تتغيّر**. تغيّرت لغة ما تحمله فقط.

## ٥ — حالات الفراغ (`FR-018`)

كل قائمة تعرّف نصّها بنفسها — عبارة واحدة عامة لا تكفي. تُبنى بالصيغة:
**سبب الفراغ + الإجراء التالي**.

| الشاشة | العنوان | الإجراء |
|---|---|---|
| `enrollments` | «لم تسجّل في أي كورس بعد» | زر «تصفّح الكورسات» |
| `exams` | «لا اختبارات متاحة الآن» | — |
| `certificates` | «لم تحصل على شهادة بعد» | «أكمل كورساً لتحصل على أولى شهاداتك» |
| `orders` | «لا طلبات في سجلّك» | — |
| `manage/courses` | «لم تنشئ كورساً بعد» | زر «أنشئ كورساً» |
| `members` | «لا أعضاء في مساحة العمل غيرك» | زر «ادعُ عضواً» |
| `workspaces` | «لا مساحات عمل» | زر «أنشئ مساحة عمل» |
| نتيجة تصفية فارغة | «لا نتائج تطابق التصفية» | زر «امسح التصفية» |

**التمييز مُلزِم**: «لا بيانات» ≠ «لا نتائج للتصفية». الأولى تدعو للإنشاء، والثانية لمسح
التصفية — وخلطهما يوقع المستخدم في طريق مسدود أمام قائمة فيها بيانات لا يراها.
