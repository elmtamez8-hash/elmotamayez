# Contract — `PaymentProviderInterface` (مُوسَّع)

**السند:** `research.md` §ح · `spec.md` `FR-001` · `NFR-003` · `NFR-005` · `NFR-011`
· إذن السبيك الصريح: «وإن احتاج فتعديله جزء من هذه المرحلة»
**مُصحَّح بعد مراجعة الوكلاء** — `review-findings.md` §أ (‏A1 · A2) و§ب (‏B1 · B2).

---

## أ — العقد القائم، ولماذا لا يكفي

```php
interface PaymentProviderInterface
{
    public function identifier(): string;
    public function createCharge(Order $order): array;
    public function verify(array $reference): array;   // {status, verified}
    public function supportsRefund(): bool;
}
```

| الفجوة | المتطلب المتعطّل |
|---|---|
| لا مدخل لحمولةٍ واردة موقَّعة | `FR-005` — التحقّق من التوقيع قبل أي أثر |
| `verify()` تأخذ مرجعاً واحداً | `FR-012` — التسوية تسأل عن **مدى**، لا عن صفٍّ تعرفه |
| لا شكل مُعلَن لصفحة الدفع | `FR-009` — لا اعتماد على عودة المستخدم |

⚠️ **و`verify()` تجيب عن السؤال الخطأ للتسوية.** هي تسأل «ما حال العملية التي أعرفها؟»،
والتسوية تسأل «**ما الذي نجح عندك ولم أعرف عنه شيئاً؟**» — وهذا الفرق هو `US2` كلها. مسحٌ
مبنيّ على `verify()` يبقى أعمى تماماً عن دفعةٍ نجحت وضاع إشعارها، وهي **الحالة التي وُجدت
التسوية لأجلها**.

## ب — العقد بعد التوسيع

```php
interface PaymentProviderInterface
{
    // — القائم، بلا تغيير في التوقيع —
    public function identifier(): string;
    public function verify(array $reference): array;
    public function supportsRefund(): bool;          // ⚠️ false دائماً، لكل مزوّد. §هـ

    /**
     * ⚠️ نوعٌ مُعلَن بدل `array` — والقيمة المعادة تسع مزوّداً بلا صفحة دفع.
     * راجع §ج: `redirectUrl` قابل للإفراغ، و`instructions` هو نصف التحويل البنكي.
     */
    public function createCharge(Order $order): ChargeIntent;

    // — المضاف —

    /**
     * هل هذه الحمولة صادرة عن المزوّد فعلاً؟
     *
     * ⚠️ تأخذ الجسد الخام لا المُفكَّك: التوقيع يُحسب على البايتات كما وصلت،
     * وأي فكٍّ ثم إعادة ترميز يغيّر ترتيب المفاتيح والمسافات فيكسر التحقّق —
     * على المزوّد الحقيقي وحده، بعد أن يكون الاختبار الوهمي أخضر.
     *
     * ⚠️ والمقارنة بزمن ثابت (`hash_equals`)، لا بـ`===`.
     *
     * ⚠️ ومزوّدٌ بلا بوابة يعيد `false` دائماً، لا `true`. راجع §هـ — هذه هي
     * الثغرة التي كادت تفتح اعتماد أي طلبٍ لمهاجم غير مصادَق.
     */
    public function verifySignature(string $rawBody, array $headers): bool;

    /** ما الذي وقع في هذه الحمولة، بلغة النظام لا بلغة المزوّد. */
    public function parseCallback(string $rawBody): CallbackEvent;

    /**
     * كل ما تغيّرت حالته لدى المزوّد في هذا المدى — لا ما نعرفه فقط.
     *
     * ⚠️ هذه دالّة التسوية، والفرق بينها وبين verify() هو US2 بأكملها.
     * ⚠️ والمدى نصف مفتوح `[from, to)` — راجع §و.
     *
     * @return iterable<CallbackEvent>
     */
    public function transactionsInWindow(CarbonImmutable $from, CarbonImmutable $to): iterable;
}
```

⚠️ **ولا `refund()` في العقد، والآن بسببٍ أدقّ.** قرار المالك (‏`Q9`، مُنقَّح ‎2026-08-11‎)
ليس «أرصدة لا نقد» بل **«مُسجَّل لا آليّ»**: المال يخرج فعلاً حين يصرّ الطالب، لكن بتحويلٍ
يدويّ يقرّره إنسان بسببه — تماماً كما يخرج أجر المدرّس اليوم عبر `RecordTeacherPayout`
(«‏Money leaves. Once per period, never negative»). فغياب `refund()` من العقد هو ما يجعل
«لا مسار آليّ يُخرج قرشاً» **قابلاً للفحص** بدل أن يكون عُرفاً. التفصيل في `research.md` §د3.

## ج — الأنواع المُعلَنة

⚠️ **ترث `DataTransferObject` بخصائص `readonly` مُرقّاة، وليست `final readonly class`.**
الصنف الأساس **مجرَّد وغير `readonly`**، وPHP ‎8.2+‎ يرفض `Readonly class cannot extend
non-readonly class` — **خطأ قاتل، لا تحذير**. والشكل أدناه هو شكل `CreditMovement` المشحون.

```php
final class ChargeIntent extends DataTransferObject
{
    public function __construct(
        public readonly string $reference,
        /**
         * ⚠️ قابل للإفراغ، وذلك هو بيت القصيد.
         *
         * التحويل البنكي **لا صفحة دفع له**، و`ManualTransferProvider` هو الربط
         * الوحيد في الحاوية اليوم ويؤكّده `PaymentTest` — أحد المسارات الحرجة
         * الثمانية التي يوقف كسرُها الدمج. حقلٌ غير قابل للإفراغ هنا كان يجعل
         * المزوّد المشحون غير قابل للتمثيل، ويكسر `FR-002` الذي تشهد الخطة
         * نفسها بأنه منفَّذ.
         */
        public readonly ?string $redirectUrl,
        /** @var array<string, mixed> تعليمات التحويل حين لا توجد صفحة. */
        public readonly array $instructions,
        public readonly ?CarbonImmutable $expiresAt,
    ) {}
}

final class CallbackEvent extends DataTransferObject
{
    public function __construct(
        public readonly string $externalId,   // مفتاح عدم التكرار
        public readonly string $reference,    // العملية التي يخصّها
        public readonly PaymentStatus $status,
        public readonly int $amountMinor,     // ⚠️ صحيح، وحدات صغرى — NFR-007
        public readonly string $currency,
        /** @var array<string, mixed> ⚠️ مُنقّى: بلا بطاقة ولا سرّ — FR-030 */
        public readonly array $safePayload,
    ) {}
}
```

**و`fromArray()` من الصنف الأساس** كما يوجب الدستور §VI.

⚠️ **`safePayload` مُنقّى عند حدود العقد، لا عند العرض.** تنقيةٌ في طبقة العرض تعني أن
الحمولة الخام كُتبت في القاعدة وفي سجلّ التطبيق أوّلاً — و`NFR-010` يمنع الثانية و`FR-030`
يمنع الأولى. فالمزوّد يسلّم نظيفاً، لأنّه وحده يعرف أيّ حقولٍ عنده حسّاسة.

⚠️ **والمرفوض توقيعه لا يمرّ من هنا إطلاقاً**، فلا `safePayload` له — وهو ما يوجب تنقيةً
ثانية مستقلّة عن المزوّد قبل تخزينه. راجع `data-model.md` §ج.

## د — ⚠️ التوقيع ليس تحقّقاً من المبلغ

**والخطة كانت تعاملهما كشيءٍ واحد.** `amountMinor` و`currency` كانا مُعلَنَين في النوع ولا
يُستعملان بعدها في أي ملف.

**السيناريو:** طالبٌ يبدأ دفع ‎٥٠٠‎ ريال، ويدفع ‎١‎ — على بوابةٍ تضع المبلغ في رابط صفحة
الدفع أو تدع الدافع يختاره، وكلاهما شائع في الدفع المستضاف والمحافظ. فيوقّع المزوّد إشعاراً
**صحيحاً تماماً**: `captured, amountMinor = 100`. فتُغلق المطالبة كاملةً وتُضاف الأرصدة
ويُرفع الحجب — والتوقيع سليمٌ في كل خطوة.

**فالقاعدة، ملزِمة في `HandleProviderCallback`:**

```
if ($event->amountMinor !== $transaction->amount_minor
    || $event->currency !== $transaction->currency) {
    → result = 'mismatch' · لا شحن · لا أرصدة · يدخل تقرير التسوية (FR-017)
}
```

**ومن هذا تُجاب حالة الحافّة «عملة الدفع تختلف عن عملة المستحق»**: لا تُقبَل ضمناً بقيمتها
الاسمية. عملةٌ مختلفة **مطابقةٌ فاشلة** ما دام الإطلاق بعملةٍ واحدة (‏`د8`)، وتُرفع إلى
إنسان بدل أن تُحوَّل بسعرٍ لا مصدر له.

## هـ — ⚠️ `manual` مزوّدٌ حيّ، و`{provider}` يختار السرّ الذي يتحقّق

**الثغرة التي كادت تُشحن:** لا شيء في الخطة كان يقول كيف يُحلّ `{provider}` إلى تنفيذ، ولا
أنّ المجهول يُرفض، ولا ماذا يعيد `manual` من `verifySignature()`. والتنفيذ «الطبيعي» لمزوّدٍ
بلا بوابة — على غرار `verify()` المشحون الذي يعيد `manual_review` — هو `return true` بمعنى
«لا شيء هنا يُتحقَّق منه».

**وعندها يُرسل مهاجمٌ غير مصادَق `POST /webhooks/payments/manual`** بجسدٍ يسمّي أي مرجع،
فيعتمد أي طلبٍ معلَّق — أو يعكس دفعة طالبٍ دفع فيعود حجبه.

**ثلاث قواعد ملزِمة:**

1. **`ManualTransferProvider::verifySignature()` تعيد `false` دائماً**، بتعليقٍ يقول لماذا:
   مزوّدٌ بلا بوابة **لا يُرسل إشعارات**، فكل ما يصل باسمه انتحال.
2. **السجلّ صريح، لا `identifier()` مسحاً على الحاوية.** المعرّف غير المسجَّل → `404`،
   والمسجَّل بلا قدرة على استقبال إشعارات → `404` كذلك. الشكل المتَّبع في المستودع هو
   وسم الحاوية (`->tag('notification.channels')`)، ويُستنسخ هنا لأنّ `NFR-003` **يقيس**
   أنّ إضافة مزوّد لا تمسّ منطق الطلبات.
3. **`404` لا `403`.** ردٌّ مميَّز يخبر المهاجم أنّ الاسم صحيح والتوقيع وحده الخطأ.

## و — المزوّد الوهمي: أداةُ اختبارٍ أولى الدرجة

`NFR-011` **يمنع** أي نداء شبكي حقيقي، ويسمّي أربع حالات:

| الحالة | ماذا تُثبت |
|---|---|
| نجاح | `SC-001` — الإشعار يفتح الوصول |
| فشل | `FR-008` — يبقى المستحق والحجب، ويُبلَّغ بسببٍ مفهوم |
| تكرار | `SC-003` — عشر مرّات، أثرٌ واحد |
| توقيع غير صالح | `SC-002` — رفضٌ **وتسجيل** |

**وثلاث يفرضها ما سبق:**

| الحالة | ماذا تُثبت |
|---|---|
| نجاحٌ **بلا إرسال إشعار** | `SC-004` — مدخل اختبار التسوية الوحيد؛ بلاها لا يُثبَت إطلاقاً |
| **مبلغٌ مخالف** بتوقيعٍ صحيح | §د — أنّ التوقيع ليس تحقّقاً من المبلغ |
| **معرّف حدثٍ جديد لكل إعادة إرسال** | أنّ عدم التكرار لا يقوم على `external_id` وحده. راجع `data-model.md` §ج |

⚠️ **ومدى التسوية نصف مفتوح `[from, to)`**، وتاليه يبدأ من `to` بالضبط. مدىً مغلق على
الطرفين يزور الثانية الحدّية مرّتين، ومفتوحٌ عليهما يُسقطها — والفرق لا يُغفَر إلا بعدم
تكرارٍ على مستوى **الأثر**، وهو ما لم يكن مضموناً قبل هذا التصحيح.

⚠️ **والوهميّ يعيش في `tests/Support/`، لا في `app/Modules/Payments/Providers/`.** مزوّدٌ
مزيّف مسجَّل في الحاوية هو مزوّدٌ يمكن أن يُختار بمتغيّر بيئة في الإنتاج فيقبل كل دفعة بلا
مال. الشكل نفسه المستعمل في `FakeBroadcastProvider`.

## ز — أنواع القيم لـLarastan L8

⚠️ **التوقيعات أعلاه تحمل `@param`/`@return` بأنواع القيم**، كما يفعل العقد المشحون
(`@return array{status: string, verified: bool}`). `array` عارية تسقط على المستوى ‎٨‎،
والخطة تلتزم **بلا baseline جديد وبلا `@phpstan-ignore`**.
