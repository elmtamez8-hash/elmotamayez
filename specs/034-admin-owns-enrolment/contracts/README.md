## ١) `POST /api/v1/cohorts/{cohort}/join` — **يُحذَف**

| | |
|---|---|
| اليوم | `201` + `CohortMembershipResource` |
| بعدَ ٠٣٤ | **المسارُ غيرُ موجود** ⇒ `404` |

⚠️ **والفعلُ `JoinCohort` يبقى**: `ApproveOrder` و`ActivateSubscription` يستدعيانِه — فهو ما يُنشئُ العضويّةَ عندَ اعتمادِ الإدارة. المحذوفُ البابُ العامُّ وحدَه.

⚠️ **والتوكيدُ على الكتابة، لا على `404`.** فشلُ هذا البندِ كتابة: مسارٌ لم يُغلَقْ يعني عضويّةً حقيقيّةً أُنشِئَت. يُقاسُ عددُ `cohort_memberships` قبلَ الطلبِ وبعدَه.

المُنادي الوحيدُ في الواجهة: `frontend/src/lib/cohorts.ts › cohorts.join` ← `components/courses/CohortPicker.tsx:51`. يُحذَفُ الاثنان.

## ٢) `cohort_gate` في حمولةِ المنهج — **المفاتيحُ تُحفَظُ، والجملةُ تتغيّر**

`CurriculumResource:77` ⇒ `'cohort_gate' => $view->cohortGate->toArray()`

```
required        bool   ← كما هو: هل تُدرَّسُ المادّةُ في مجموعات؟
satisfied       bool   ← كما هو: هل للطالبِ عضويّةٌ مفتوحة؟
joinable_exists bool   ← كما هو: هل ثمّةَ مجموعةٌ صالحة؟
message         string ← يتغيّرُ نصُّه وحدَه
```

⚠️ **لا يُحذَفُ مفتاحٌ ولا يُضافُ**، لأنّ الصفحةَ **تقرأُ** الحكمَ ولا تُعيدُ اشتقاقَه — وإعادةُ اشتقاقِ `status === "open" && !is_full` في TypeScript هي عينُ عطبِ «تهجئتَين لسؤالٍ واحد» الذي جعلَ تسجيلاً مدفوعاً غيرَ قابلٍ للفتحِ في ٠١٨.

⚠️ **و`joinable_exists` تبقى رغمَ أنّها لم تعُدْ تقفِلُ شيئاً**: الشاشةُ تُميِّزُ بها «ثمّةَ مجموعاتٌ ولم تُسنَدْ إليها بعد» من «هذا الكورسُ بلا مجموعاتٍ أصلاً» — جملتانِ مختلفتانِ تماماً للطالب.

| الحال | ما يُقال |
|---|---|
| `required: false` | لا جملة (المنهجُ مفتوحٌ ولا مجموعةَ في الأمرِ أصلاً) |
| `required · satisfied` | لا جملة |
| `required · ! satisfied · joinable_exists` | «لم تُسنَدْ إلى مجموعةٍ بعد. الإدارةُ هي مَن يُسنِد — راجِعْ ‹جهة›.» |
| `required · ! satisfied · ! joinable_exists` | «لا مجموعةَ متاحةً في هذا الكورسِ الآن — راجِعْ ‹جهة›.» (كما هو اليوم) |

**والمنهجُ مفتوحٌ في الأربع.**

## ٣) `PlanResource` — الصلاحيّةُ نفسُها، والبابُ يُفتَح

```
canViewAny()  Permissions::PLANS_PRICE   ← كما هو
canCreate()   false ⇒ Permissions::PLANS_PRICE
```

⚠️ **لا صلاحيّةَ ثانية.** مَن يُسعِّرُ الباقةَ هو مَن يُنشئُها بالنيابة؛ اختراعُ `plans.create.onBehalf` جوابٌ ثانٍ لسؤالٍ له جوابٌ، ويصيرُ صنفاً منصّيّاً جديداً لا يحملُه أحد.

⚠️ **وحقلُ المدرّسِ مطلوبٌ في النموذج، ومرفوضٌ في الفعلِ أيضاً.** النموذجُ يُشكِّلُ طلباً واحداً ولا يُشكِّلُ الذي بعدَه — والبذورُ والمستوردُ يصلانِ `SavePlan` بلا نموذجٍ خلفَهما. `SavePlan` يأخذُ `$workspaceId` وسيطاً صريحاً أصلاً، فالرفضُ حيثُ يُقرَأ.
