# دستور منصة mteatch

منصة تعليمية متعدّدة المستأجرين (SaaS): كورسات ← تسجيل ← اختبارات ← شهادات ← مدفوعات يدوية.
هذا الدستور يعلو على أي عادة أو تفضيل شخصي في هذا المستودع.

## Core Principles

### I. عزل المستأجرين (Tenant Isolation) — غير قابل للتفاوض

تسريب بيانات بين مساحات العمل هو أخطر عطل ممكن في هذا المنتج، وهو صامت بطبيعته.

- كل نموذج مملوك لمستأجر **يجب** أن يستخدم `BelongsToWorkspace`. لا استثناء.
- التحقق من وجود سجل تابع لمستأجر **يجب** أن يمرّ عبر `WorkspaceRules::exists('table')`.
  استخدام `'exists:table,id'` على جدول تابع لمستأجر **ممنوع** — قاعدة Laravel استعلام خام يتجاوز النطاق العام.
- كل استدعاء `Model::search()` **يجب** أن يقيّد نتائجه صراحةً بـ `->where('workspace_id', ...)`،
  لأن Scout يستعلم من المحرّك خارج النطاقات العامة.
- أي تجاوز متعمّد للنطاق (`withoutWorkspaceScope()` أو `WorkspaceContext::withoutScope()`)
  **يجب** أن يحمل تعليقاً يشرح السبب، و**يجب** أن يغطّيه اختبار.
- خارج دورة HTTP (وظيفة في الطابور، أمر كونسول) **يُمنع** استدعاء `WorkspaceContext::set()`؛
  الاستخدام الوحيد المسموح هو `forWorkspace($workspace, fn () => ...)`.
  السبب: `WorkspaceContext` مفردة على مستوى التطبيق تُخزّن نتيجتها، فالضبط المباشر يسرّب
  مساحة العمل إلى المهمة التالية التي يعالجها نفس العامل.
- كل نموذج جديد تابع لمستأجر **يجب** أن يُضاف له حالة في
  `tests/Feature/Tenancy/WorkspaceIsolationTest.php` في نفس الـ PR.

**سبب الصرامة**: نموذج بلا `BelongsToWorkspace` يعمل بشكل سليم تماماً في كل اختبار قائم،
ويسرّب البيانات بصمت في الإنتاج. لا توجد بوابة آلية تكشفه — الاختبار المضاف هو البوابة.

### II. المنطق في الـ Actions (Actions Own Business Logic)

- منطق الأعمال يعيش في `Actions/` (`App\Shared\Actions\Action`، دالة عامة واحدة `handle()`).
  **يُمنع** وضعه في المتحكّمات أو الموارد أو موارد Filament.
- تسلسل المتحكّم إلزامي: Form Request للتحقق ← بناء DTO ← استدعاء Action ← إرجاع API Resource.
- أي قاعدة عمل مضبوطة على نموذج (حدود المحاولات، المؤقتات، ترتيب الدروس، شروط الأهلية)
  **يجب** أن تُفرض داخل الـ Action الذي ينفّذ العملية، لا في التحقق فقط.

**السبب**: الـ Action هو المدخل الوحيد المشترك بين الـ API والـ Seeders ولوحة Filament.
قاعدة مفروضة في `FormRequest` وحده تُلتَف عليها من لوحة الأدمن بلا أثر.

### III. استقلال الوحدات والتكامل بالأحداث (Module Autonomy via Events)

- **يُمنع** استدعاء `Actions` أو الوصول لتفاصيل نماذج وحدة أخرى مباشرةً من داخل وحدة.
  التكامل بين الوحدات يتم بحدث نطاق (domain event) ومستمع يُسجَّل بـ `Event::listen()`
  في `boot()` الخاص بمزوّد الوحدة المشتركة.
- **يُمنع** تسجيل مزوّد وحدة يدوياً في `bootstrap/providers.php` — الاكتشاف تلقائي عبر
  `App\Shared\Modules\ModulesServiceProvider`.
- مجلد الهجرات **يجب** أن يكون `Database/Migrations` بحرف M كبير بالضبط.
  خطأ في حالة الأحرف يعمل على Windows/macOS ويحمّل **صفر** هجرات على Linux بصمت.
- كل وحدة جديدة **يجب** أن تُضاف إلى `phpstan.neon` ليقرأ هجراتها ويستنتج أنواع الخصائص.

### IV. البوابات الآلية خضراء (Green Gates)

قبل دمج أي تغيير، الأربعة معاً **يجب** أن تمرّ:

| البوابة | الأمر |
|---|---|
| الاختبارات | `php vendor/bin/pest` |
| نمط الكود | `./vendor/bin/pint --test` |
| التحليل الساكن | `./vendor/bin/phpstan analyse` (Larastan level 8) |
| أنواع الواجهة | `npx tsc --noEmit` |

- شجرة PHPStan نظيفة اليوم على المستوى 8 و**يجب** أن تبقى كذلك.
  **يُمنع** إسكات خطأ بـ baseline جديد أو `@phpstan-ignore` لتمرير البوابة —
  الإسكات المقبول الوحيد هو ما يوثَّق سببه في نفس السطر ويوافق عليه المراجع.
- المسارات الحرجة الثمانية في `AGENTS.md` (عزل مساحات العمل، فرض الأذونات، التسجيل وتقييد
  الدروس، إتمام الكورس، تسليم الاختبار والتصحيح، إصدار الشهادة وعدم تكرارها، التحقق من الشهادة،
  اعتماد الدفع ← إنشاء التسجيل) **يجب** أن تبقى خضراء. كسر أي منها يوقف الدمج.
- اختبارات الميزات (Feature) هي شبكة الأمان الأساسية، لا اختبارات الوحدة.

### V. التفويض بالسياسات والثوابت (Policy-Based Authorization)

- التفويض عبر السياسات في `{Module}/Policies/`.
- أسماء الأذونات **يجب** أن تُؤخذ من ثوابت `Tenancy\Support\Permissions`
  وأسماء الأدوار من `Tenancy\Support\Roles`. **يُمنع** كتابة اسم إذن أو دور كنص حرفي.
- spatie/permission يعمل في وضع الفرق بـ `team_id = workspace_id`؛ أي فحص صلاحية قبل ضبط
  معرّف الفريق بلا معنى. الاختبارات **يجب** أن تمرّ عبر `WorkspaceContext::set()`
  أو مساعدات `WithWorkspace`.
- Super Admin هو العلم `users.is_super_admin` على مستوى المنصة، **وليس** دوراً داخل مستأجر.
- **يُمنع** إدخال أي سرّ أو مفتاح أو بيانات اعتماد إلى المستودع.

### VI. العقود الظاهرة مقصودة (Deliberate Public Contracts)

- النماذج تستخدم `HasUuid` و`getRouteKeyName()` هو `uuid`.
  المسارات وحمولات الـ API **يجب** أن تكشف `uuid` فقط — **يُمنع** كشف المعرّف التسلسلي.
- كل استجابة API تمرّ عبر API Resource، لا نموذج مُسلسل مباشرةً.
- كل ملف PHP يبدأ بـ `declare(strict_types=1);`.
- الـ DTOs ترث `App\Shared\Data\DataTransferObject` بخصائص `readonly` مُرقّاة ومُنشئ `fromArray()`.
- مزوّدو الدفع خلف `Payments\Contracts\PaymentProviderInterface`.
  إضافة مزوّد جديد **يجب ألا** تتطلّب تعديل منطق الطلبات أو التسجيل.
- تغيير كاسر في الـ API **يجب** أن يوثَّق ويصدر تحت مسار إصدار جديد، لا أن يُعدَّل مكانه.

## قيود البيئة والتقنية (Environment & Technical Constraints)

- **حزمة التقنية ثابتة**: الخلفية Laravel 13 / PHP 8.5 كأحادية معيارية،
  الواجهة Next.js 15 (App Router, TypeScript, Tailwind).
  إدخال إطار عمل أو لغة جديدة يتطلّب تعديل هذا الدستور أولاً.
- **تكافؤ البيئات**: التطوير المحلي على SQLite والإنتاج على MySQL في الوضع الصارم.
  SQLite **يخفي أخطاء عرض الأعمدة** — يقبل أي عدد صحيح في عمود `unsignedInteger`.
  عند كتابة قيم رقمية **يجب** مراجعة الهجرة والتأكد أن MySQL الصارم سيقبلها.
- **الاختبارات** على SQLite في الذاكرة مع `SCOUT_DRIVER=null`.
  في الاختبارات، أول استدعاء لـ `WorkspaceContext::id()` يجمّد النتيجة —
  الاستعلام عن نماذج المستأجر **يجب** أن يأتي بعد `Sanctum::actingAs()` أو `setCurrentWorkspace()`.
- **المصانع (Factories)** تُحلّ مركزياً عبر `AppServiceProvider::guessFactoryName()`.
  **يُمنع** تعريف `newFactory()` على النماذج.
- **مصادقة الـ API** برموز Sanctum الحاملة؛ لوحة `/admin` بالجلسات ومحميّة بـ `EnsureFilamentAccess`.
- **يُمنع** تشغيل `npm run build` وخادم `npm run dev` معاً — كلاهما يكتب في `.next/`
  وخادم التطوير يموت بـ `Cannot find module './NNN.js'`.

## سير العمل وبوابات الجودة (Workflow & Quality Gates)

- **دورة Spec Kit** للعمل ذي الحجم المعتبر:
  `/speckit-specify` ← (`/speckit-clarify` عند الحاجة) ← `/speckit-plan` ← `/speckit-tasks` ← `/speckit-implement`.
  الإصلاحات الصغيرة والتصحيحات معفاة.
- **يُمنع** الانتقال إلى `/speckit-plan` ومواصفة الميزة تحتوي علامات `[NEEDS CLARIFICATION]`
  غير محسومة، أو بنوداً راسبة في `checklists/requirements.md`.
- **التوثيق يتحرّك مع الكود**: تعديل يمسّ الوحدات أو نقاط النهاية أو الأذونات **يجب** أن
  يحدّث `docs/README.md`؛ وتعديل المخطّط يحدّث `docs/erd.md`؛
  وتعديل التعليمات التشغيلية يحدّث `CLAUDE.md` و`AGENTS.md` معاً.
- **مراجعة الكود** تتحقّق صراحةً من المبادئ I و IV و V. مراجع يوافق على PR يضيف نموذجاً
  تابعاً لمستأجر بلا `BelongsToWorkspace` وبلا اختبار عزل يتحمّل المسؤولية مع الكاتب.
- **تبرير التعقيد**: أي تجريد أو طبقة أو تبعية جديدة **يجب** أن تُبرَّر في وصف الـ PR
  بمشكلة قائمة الآن، لا بحاجة متوقعة. الحل الأبسط الذي يعمل هو الحل الصحيح.

## Governance

- هذا الدستور يعلو على أي عادة أو تفضيل شخصي. عند التعارض، الدستور يفوز.
- **التعديل** يتطلّب: (١) توصيف التغيير وسببه، (٢) موافقة مالك المستودع،
  (٣) خطة ترحيل للكود المخالف إن وُجد، (٤) تحديث هذا الملف ورقم إصداره في نفس الـ PR.
- **سياسة الإصدارات** (SemVer):
  - **MAJOR**: حذف مبدأ أو إعادة تعريفه بما يكسر التوافق مع ممارسة قائمة.
  - **MINOR**: إضافة مبدأ أو قسم جديد، أو توسيع جوهري لإرشاد قائم.
  - **PATCH**: توضيح صياغة أو تصحيح لا يغيّر المعنى.
- **مراجعة الامتثال**: كل PR يُراجَع مقابل المبادئ الستة. المبدأ I يُفحص يدوياً في كل PR
  يضيف نموذجاً أو استعلاماً، لأنه المبدأ الوحيد بلا بوابة آلية تحرسه.
- **الإرشاد التشغيلي اليومي** في `CLAUDE.md` و`AGENTS.md`. الدستور يحكم *ماذا يُسمح*،
  وتلك الملفات تشرح *كيف يُنفَّذ*. عند تعارضهما مع الدستور، الدستور هو المرجع
  ويُصحَّح الملف المخالف.
